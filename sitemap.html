Information Architecture Analysis

Current Model

Type: Hub-and-spoke with isolated pages

Home page (index) links outward to 6 standalone reference documents. Each standalone page is self-contained with no internal navigation back or between pages.

User Journeys & Flows

Journey 1: "I want to learn how to use Readworthy"

Current path: Home → Guide → (stuck, no clear next step)

Problem: After reading the guide, user has no context on when/how to apply it. No link to compatibility matrix, CLI reference, or back to home.

Journey 2: "I want to understand the philosophy"

Current path: Home → Research Brief → (stranded)

Problem: Each research/reference page is isolated. No way to navigate between related concepts (e.g., from Research Brief to Naming Brief to CLI Architecture).

Journey 3: "I want to decide if Readworthy fits my use case"

Current path: Home → Compatibility Matrix → (stuck)

Problem: Compatibility matrix is thorough but disconnected from decision-making context (research, examples, guides). Hard to move from "should we use this?" to "how do we use it?"

Journey 4: "I want to implement the CLI"

Current path: Home → CLI Architecture → (stuck, no implementation guide)

Problem: Architecture doc exists but no implementation guide, code examples, or integration instructions.

Issues & Gaps

1. Pages are isolated (no internal cross-links)

Each page is self-contained. There's no way to navigate between guide, research, and reference without returning to home. This breaks exploration and discovery.

2. No breadcrumb navigation

Users don't know their location in the site hierarchy or how to navigate back except by browser back button.

3. Unclear information hierarchy

It's not obvious which pages are "getting started," "learning," "reference," or "philosophy." Content categories are implicit, not explicit.

4. No clear learning path

Optimal learning order might be: Home → Naming/Philosophy → Research Brief → Guide → Compatibility → CLI. But nothing suggests this path.

5. Video-summary is an orphan

Standalone example with no context, no return link, no indication of what it demonstrates or why it matters.

6. No section headers or grouping

The home page has 6 independent cards. No categories like "Learn," "Explore Philosophy," "Reference Docs" to set expectations.

7. No search or index

Six separate pages with no way to search or index content across the site.

8. Incomplete navigation in index.html

Home page doesn't link to all pages (Naming Brief is missing from top-level navigation).

Recommendations for Improvement

Priority 1: Fix Navigation (Quick wins)

1.1 Add breadcrumb navigation to all pages

Each page should show: Home / [Category] / [Page Title]

Why: Users know where they are and can jump back to category or home.

1.2 Add "Back to Home" footer link on all pages

Every page needs at least one way back to index.html.

Why: Users shouldn't be stranded.

1.3 Add internal cross-links by category

Example: At the end of Guide, add "Related: Compatibility Matrix, Video Example"

Why: Helps users discover related content without returning home.

1.4 Update index.html navigation to include all 6 pages

Currently missing Naming Brief from main nav. Add it or reorganize.

Why: Consistency and completeness.

Priority 2: Improve Information Architecture

2.1 Reorganize home page with category headers

Group cards into sections:

START HERE
├── Guide (learn to use)
├── Example (see it working)

UNDERSTAND THE CONCEPT
├── Philosophy/Research
├── Naming Brief
├── Compatibility Matrix

IMPLEMENT
├── CLI Architecture

Why: Makes purpose of each page clear and guides user flow.

2.2 Create a learning path / guided tour

Add optional "Learning Path" on home with recommended reading order:

  1. What is Readworthy? (Home)
  2. Why does this matter? (Naming Brief → Research Brief)
  3. When should I use it? (Compatibility Matrix)
  4. How do I use it? (Guide → Example)
  5. How do I build it? (CLI Architecture)

Why: Guides users through optimal discovery without forcing it.

2.3 Add section landing pages (optional enhancement)

For advanced users, create intermediate hubs:

  • learn.html - Guide + examples + best practices
  • reference.html - Compatibility, CLI, decision matrices
  • research.html - Philosophy, naming, thesis

Why: Reduces cognitive load for users with specific goals.

Priority 3: Improve Video-Summary Page

3.1 Add header/context to video-summary.html

Currently it's a bare example. Add:

  • Page title and brief explanation of what this example demonstrates
  • Navigation back to home / guide
  • Related examples or next steps

Why: Users understand context and can navigate onward.

Priority 4: Enhance Home Page UX

4.1 Add a quick "What is Readworthy?" explainer section above cards

Current layout jumps into navigation. Add context first:

TITLE: AI-native docs worth reading

EXPLAINER:
Readworthy is a documentation framework for turning bloated,
repetitive AI-generated text into structured, readable documents
for both humans and AI agents.

[View live site →]

EXPLORE:
[cards with categories]

4.2 Add a "Popular Paths" section

Show quick links for common questions:

  • "I want to learn Readworthy" → Guide
  • "Should I use HTML or Markdown?" → Compatibility
  • "I want to understand the philosophy" → Research Brief
  • "I want to build the CLI" → CLI Architecture

4.3 Add a footer with all links + sitemap

Every page should have footer with:

  • All page links organized by category
  • Social links (GitHub, etc.)
  • Link to this sitemap

Priority 5: Add Global Navigation

5.1 Add sticky header with site logo + main nav

Every page should have consistent header with:

  • Readworthy logo/home link
  • Main navigation: Home, Guide, Reference, Research
  • Search (optional future enhancement)

Why: Users can navigate without clicking back.
