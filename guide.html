Readworthy Guide

Markdown-Flavored HTML

A tiny CSS library that improves the reading experience for AI-generated text output by turning plain documents into semantic, styled HTML artifacts.

← Home Styling Guidance Components Output Example

Core Idea: HTML replaces Markdown when the file is no longer just writing. It becomes an interface, spec, artifact, or agent-readable product.

Styling Guidance for Replacing .md with .html

Use this mental model:

Markdown HTML Replacement
Markdown file HTML document
Markdown syntax Semantic tags
Markdown theme CSS design system
Markdown blocks Reusable components

Recommended Base Structure

<body class="doc">
  <header class="doc-hero">
    <p class="eyebrow">Project Spec</p>
    <h1>Page Title</h1>
    <p class="lede">Short summary.</p>
  </header>
  <nav class="toc"></nav>
  <main class="prose">
    <section>
      <h2>Section Title</h2>
      <p>Content...</p>
    </section>
  </main>
</body>

Core Styling Rules

.prose {
  max-width: 72ch;
  margin-inline: auto;
  line-height: 1.65;
}

.callout,
.timestamp,
.spec-card {
  border-top: 1px solid var(--rw-border);
  margin-block: 1rem;
  padding-block: .75rem;
}

Install-Time Design References

readworthy.css should ship with neutral defaults, then prompt users during setup to provide their own design reference for colors, fonts, spacing, and component tone. The library should not inherit Sprintz-specific colors, type, or brand rules.

Atomic Design Layers

Layer Description
Atoms HTML primitives like headings and paragraphs.
Molecules Reusable UI groupings like callouts.
Organisms Full content sections and layouts.
Templates Complete documents and article systems.

Usage

<link rel="stylesheet" href="readworthy.css">

Component Examples

These components turn plain documentation into structured, reusable, agent-friendly interfaces while keeping the stylesheet adaptable through CSS variables.

.badge

Small metadata labels or status indicators. Use them for version labels, experimental features, AI model compatibility, tags, categories, and status indicators.

Beta GPT-5 Ready Docs

Ideal for repo READMEs, agent skills, product docs, and changelogs.

.note

Low-priority supplemental context: additional explanations, best practices, optional guidance, and UX recommendations.

This workflow also works in Claude Code.

Tone: informational and calm.

.warning

Critical caveats or failure points: breaking changes, security concerns, validation requirements, unsupported workflows, and dangerous operations.

Do not expose API keys in public repos.

Tone: high visibility and actionable.

.example

Concrete demonstrations: code snippets, HTML patterns, prompt examples, API requests, and CSS recipes. 

npm install readworthy

Purpose: reduce ambiguity for both humans and agents.

.checklist

Task-oriented procedural flows for install guides, setup instructions, QA validation, launch procedures, and agent workflows.

  • Install dependencies
  • Configure tokens
  • Run validation

Especially useful for install.md, onboarding flows, and repo setup.

.file-tree

Visual representation of project structure for repo scaffolding, agent folder structures, monorepos, and documentation systems. 

project/
├── agents/
├── prompts/
├── templates/
└── install.md

HTML keeps this representation open to later interaction: collapsible folders, search, or file annotations.

.spec-card

Self-contained system or feature definitions: component specs, API endpoint descriptions, agent definitions, prompt modules, and feature breakdowns.

Validation Agent

Ensures outputs comply with design.md.

Think of it as a documentation-native card component.

.prompt-block

System Prompt
You are a frontend architect.
Summarize this transcript as semantic HTML.
Use timestamp sections, short headings, and clear supporting notes.

Use prompt blocks for system prompts, agent instructions, Codex skills, Claude templates, and reusable workflows. This is not just code formatting: it is semantic AI instruction formatting.

.agent-instruction

Always validate HTML against design tokens.

Use for agent constraints, validation logic, workflow sequencing, tool usage policies, and role definitions.

Difference from .prompt-block: prompt blocks hold reusable prompt text; agent instructions define operational execution logic.

.validation-rule

Formal output constraints for QA requirements, design.md enforcement, accessibility checks, schema validation, and brand consistency.

  • Only one H1 per page
  • All buttons require accessible labels
  • Measure must not exceed 72ch

Extremely valuable for AI-generated assets, automated review pipelines, and agentic systems.

The Bigger Shift

Markdown documents are mostly text blobs: linear, presentation-light, and limited as reusable interfaces. readworthy.css components transform docs into semantic systems.

Old Markdown HTML Component System
Notes Interfaces
Pages Structured artifacts
Text Semantic systems
Files Reusable components
Static docs Agent-operable documents

This is why HTML becomes more powerful in AI-native workflows: the document itself becomes executable structure.
