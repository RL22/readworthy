Naming Decision Brief

Readworthy

A naming decision brief for the AI-native documentation project formerly known internally as mk2html.

← Home Decision Alignment Positioning
Decision: The umbrella brand for the project is Readworthy.

Decision Summary

We are moving forward with Readworthy as the umbrella brand for the project formerly referred to as mk2html, HTML-first agent docs, markdown-to-html operational docs, and context-optimized AI documentation tooling.

The name shifts the project away from implementation mechanics and toward the real user outcome: AI-generated documentation that is actually worth reading.

Why Readworthy?

The project is no longer just a converter. The original concept started around translating Markdown-style documentation into semantic HTML, but the deeper insight is that the real problem is not Markdown itself.

Core insight: AI-generated documentation is increasingly difficult, bloated, repetitive, and unpleasant to read.

Readworthy captures the project’s actual value proposition: 

Making AI-native documentation readable, structured, and operationally useful.

Earlier names such as mk2html, SpecFlow, ContextKit, and StructLayer described mechanisms. Readworthy describes the outcome.

Alignment with Project Goals

Goal 1

Human-readable AI documentation

Readworthy supports the belief that AI-generated docs should be engaging, visually scannable, and operationally useful by design.

Goal 2

Compatibility-first architecture

The name does not position the project as anti-Markdown. It supports a compatibility-first approach where Markdown remains useful for routing and discovery.

Goal 3

Context efficiency

Readworthy aligns with reducing context waste, improving progressive disclosure, and restructuring documentation so agents only load what they need.

Goal 4

Long-term extensibility

Readworthy scales beyond HTML, CSS, and Markdown conversion into auditing, validation, rendered AI artifacts, and documentation orchestration.

Architecture Philosophy

The name works because it supports the project’s nuanced technical philosophy: 

.md   = compatibility, discovery, activation
.html = structured operational docs
.css  = presentation layer

This keeps the project from being framed as “Markdown versus HTML.” The better positioning is:

Readworthy is a readability layer for AI-native documentation.

Branding Umbrella

Layer Name Usage
Umbrella product Readworthy The main project, product, and ecosystem name.

Recommended Positioning

Short Positioning

AI-native docs optimized for readability, structure, and context efficiency.

Expanded Positioning

Readworthy transforms bloated AI-generated documentation into structured, scannable, operational artifacts designed for both humans and agents.

Naming Conflict Review

A lightweight web review was performed against OSS, AI/devtool, GitHub, and general search contexts.

Previously rejected names

Name Reason rejected Reference
SpecFlow Existing major testing framework and related AI methodology overlap. specflow.com
ContextKit Existing OSS/devtool usage. GitHub: FlineDev/ContextKit
LayerDocs Documentation/product overlap. Layer docs
AgentPaper Existing design/paper brand usage. agentpaper.com
DocSkin Existing markdown/PDF styling package. piwheels: docskin
DocOps HTML Too close to active DocOps ecosystem. Write the Docs: DocOps

Readworthy conflict status

No dominant AI/devtool/documentation platform appears to own “Readworthy” in the reviewed context. Existing use appears mostly limited to general editorial or readability phrasing.

Because “readworthy” is a common English adjective, scattered editorial/blog usage or unavailable domains/social handles may exist. Still, the name appears substantially cleaner than prior candidates in the AI documentation tooling space.

Final Recommendation

Move forward with Readworthy.

It best captures the emotional problem, the technical philosophy, the product direction, and the long-term ecosystem opportunity.
