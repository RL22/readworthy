Readworthy research brief

HTML-First Agent Docs

A compatibility-first argument for semantic HTML as the structured operational layer for AI, product, design, and agent documentation.

← Home Why this exists Compatibility Architecture
Thesis: Markdown remains the ecosystem compatibility layer. HTML becomes the operational layer only when a document benefits from semantic structure, visual rendering, reusable components, validation, or progressive disclosure.

Why this proposal exists

Markdown won because it is portable, readable in raw form, Git-friendly, and easy for humans and models to scan. The problem is not Markdown itself. The problem is unstructured instructional prose that grows into bloated specs, repeated context, and hard-to-validate agent instructions.

readworthy.css proposes a disciplined middle path: keep required .md files where ecosystems expect them, but move high-structure operational material into lean, semantic HTML references.

Recommended architecture

project/
├── README.md                  # compatibility / repository discovery
├── AGENTS.md                  # coding-agent routing
├── SKILL.md                   # skill activation, when relevant
├── install.md                 # setup fallback
│
├── docs/
│   ├── index.html             # rich project overview
│   ├── product.html           # canonical product spec, when justified
│   ├── brand.html             # canonical brand spec, when visual examples matter
│   ├── design.html            # visual design system / tokens / components
│   ├── validation.html        # structured validation rules
│   └── workflows.html         # operational workflows
│
└── assets/
    └── readworthy.css            # render layer, not default agent context

Anti-bloat rule

Never load both a full Markdown document and its full HTML duplicate.

Markdown should route. HTML should operate. CSS should render.

When HTML earns its keep

Structured validation

Use HTML when requirements should be grouped, labeled, filtered, or validated as discrete rules.

Reusable components

Use HTML for prompt blocks, spec cards, checklists, examples, warnings, and agent instructions.

Visual fidelity

Use HTML for design systems, brand guides, component previews, annotated examples, and rendered docs.

Progressive disclosure

Use HTML references only when the agent needs deeper operational detail for the task.

When Markdown should stay

  • SKILL.md when a skill host requires it.
  • AGENTS.md when a coding agent expects it for repo instructions.
  • README.md, CHANGELOG.md, CONTRIBUTING.md, and LICENSE where GitHub/package ecosystems expect Markdown or plain text.
  • Short instructions that do not benefit from visual layout, semantic grouping, or validation.

Baseline: Anthropic PDF Skill

Anthropic’s public PDF skill is a useful benchmark because it is a real published skill with a required SKILL.md, detailed instructions, and additional references. GitHub reports the file as 314 lines and 7.88 KB.

Important: Token savings are not automatic. HTML becomes efficient only when semantic structure replaces repeated explanation. If the system stores full Markdown plus full HTML duplicates, token usage gets worse.

Design principle

.md   = compatibility, discovery, activation, routing
.html = structured operational docs, when justified
.css  = presentation only, never default agent context
