How we got here

AI tools generate enormous amounts of documentation: specs, summaries, research briefs, workflow guides. The machine layer runs on Markdown — it's portable, required by most tools, and right for agent-to-agent logic. But when that output reaches a human reader, Markdown breaks down. Long AI-generated Markdown is hard to read, harder to navigate, and impossible to scan.

In 2026, Anthropic engineer Thariq Shihipar named what many teams were already feeling:

"The chance of someone actually reading your spec, report or PR writeup is much much higher if it's in HTML."

Thariq Shihipar, Anthropic

The consensus has settled. Markdown stays in the machine layer — routing, config, agent instructions. HTML is for the output humans have to read. Readworthy is the CSS layer that makes producing it practical.

The approach

Generate HTML only where structure creates reading value and Markdown isn't required. Readworthy handles the HTML side: a single CSS file and component vocabulary that turns AI-generated content into readable artifacts — headers, callouts, spec cards, code blocks, warnings, checklists.

Core model: Markdown routes. HTML reads. CSS renders.

Use Readworthy when the document leaves the machine layer. When it becomes a spec a team reviews, a brief stakeholders will read, or a reference someone opens in a browser — that's when HTML earns its place. When it's routing logic, a config file, or a quick note, keep Markdown.

The HTML tax

HTML costs more tokens than Markdown when loaded as model context. The same content as HTML can run 1.5 to 2 times more tokens. This is real and worth understanding.

Readworthy documents are render targets, not model context. Your AI generates the HTML once; your team reads it many times. The token overhead lives in the generation step, not in every subsequent read.

Keep Markdown as your routing and compatibility layer. Use HTML for the outputs that need to be read.
