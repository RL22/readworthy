Can I Use HTML-First Agent Docs?

A caniuse-style guide for deciding where HTML can replace, supplement, or should avoid replacing common Markdown spec files.

← Home Status Key Matrix Limitations
Short answer: HTML is useful today as a reference and operational layer. It is not universally supported as the required entrypoint for Markdown-native tools.

Status key

Supported

HTML can be used directly with low compatibility risk.

Partial

HTML can be canonical or supplemental, but Markdown is still needed for ecosystem routing.

Markdown required

The tool or ecosystem expects Markdown or plain text.

Not recommended

HTML adds more markup than value for this file type.

Current limitations

HTML-only is not a universal replacement

Many tools discover instructions by exact filenames such as README.md, AGENTS.md, or SKILL.md. A standalone new-skill.html will not satisfy those requirements unless the host explicitly supports it.

HTML can introduce waste

Full Markdown plus full HTML duplicates increase context and maintenance cost. The recommended approach is a lightweight Markdown loader plus targeted HTML references.

CSS is not reasoning context

Agents usually do not need the full stylesheet. CSS is for rendering, visual inspection, and publication—not default task reasoning.

Recommended compatibility contract

1. Preserve required Markdown files.
2. Keep Markdown loaders concise.
3. Generate HTML only where structure creates value.
4. Never duplicate full canonical content across MD and HTML.
5. Use task-triggered progressive disclosure.
6. Exclude CSS from default agent context.

Decision checklist

  • Does an ecosystem require this exact Markdown filename?
  • Does the doc benefit from semantic sections, cards, or validation rules?
  • Will HTML reduce prose or merely wrap it?
  • Can the agent load only the relevant section?
  • Can the Markdown file remain a short compatibility layer?
