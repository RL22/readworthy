This archive synthesizes the original thread and the three days of ecosystem response that followed.

The Thread

Thariq Shihipar 10:42 AM · May 8

HTML is the new markdown.

Shihipar opens the thread with a statement: "I've stopped writing markdown files for almost everything and switched to using Claude Code to generate HTML for me." He argues the chance of someone actually reading a spec, report, or PR writeup is much higher if it's in HTML — it renders immediately, looks structured, and doesn't require a Markdown viewer to appreciate.

The chance of someone actually reading your spec, report or PR writeup is much much higher if it's in HTML.

Simon Willison 11:15 AM · May 8

A confirmation from the field

Willison quoted the thread with immediate endorsement, noting he had independently switched his AI explanation workflow to HTML artifacts. "The HTML explainer model works remarkably well — you can pack a lot of semantic structure into a document that renders well anywhere." He shared a recent example: an HTML explainer for a complex API change that would have taken 800 words of Markdown to convey with the same clarity.

Willison later expanded this into a full blog post at simonwillison.net/2026/May/8/unreasonable-effectiveness-of-html/ which became the definitive reference for the pattern.
Omar Sar 12:03 PM · May 8

LLM Wikis and HTML Artifacts

Omar Sar extended the thesis: "We've been calling these 'LLM Wikis' internally. HTML artifacts aren't just better docs — they become personalized operational dashboards. An agent that generates your weekly status as an HTML artifact with navigation, highlights, and a risk section is something you actually open on Monday morning."

HTML artifacts aren't just better docs — they become personalized operational dashboards. An agent that generates your weekly status as a structured, navigable artifact is something you actually open.

HN thread 1:47 PM · May 8

The token cost objection

A Hacker News thread opened shortly after the X thread and immediately surfaced the main counterargument. Top comment: "HTML costs 1.5–2× more tokens than equivalent Markdown. For docs that get loaded into model context repeatedly, this is a real cost, not a footnote."

The main counterargument

HTML as model context costs approximately 1.7× more tokens than equivalent Markdown. For documents that are repeatedly loaded as agent context, this overhead compounds. The token cost is real and not dismissible.

Thariq's reply addressed this directly: "Readworthy documents are render targets, not model context. You generate the HTML once; your team reads it many times. The token overhead lives in the generation step, not in every subsequent read."
Adithya Giridharan 3:22 PM · May 8

Agent skills as structured folders

Giridharan published a Medium post synthesizing the thread into an architectural recommendation: agent skills should be structured as folders containing a short Markdown router (SKILL.md, AGENTS.md, CLAUDE.md) and a set of HTML reference files. This became the foundational argument for why Markdown and HTML are not competing formats but complementary layers.

The Markdown file is the door. The HTML files are the rooms. Keep the router tiny and ecosystem-compatible. Put the richness in the HTML references that agents load on demand.

Ecosystem Reactions

Camp

Experimenters

Developers who immediately tried HTML artifacts and reported results within 24 hours of Shihipar's thread. Simon Willison is the archetype — he shipped an HTML explainer workflow before the thread was a day old. Finding: HTML explanations communicate complex topics more efficiently than equivalent Markdown, especially for non-technical stakeholders.

Camp

Operators

Teams using HTML artifacts as ongoing operational surfaces, not just one-time documents. Omar Sar's "LLM Wiki" framing resonated here. Finding: when artifacts are structured for navigation rather than reading, they become reference surfaces people actually return to — similar to an internal wiki, but generated rather than maintained.

Camp

Skeptics

The HN contingent focused on token cost, portability, and the illegibility of HTML diffs in pull requests. Finding: the concerns are real for specific contexts (docs-as-context, version control). The thread did not fully address these cases, which is why the "Markdown routes, HTML operates" framing emerged as a synthesis.

Camp

Builders

People who went looking for a CSS system to standardize HTML artifact output after reading the thread — the demand signal that led to Readworthy. Finding: producing HTML artifacts consistently required either a framework (too much) or inline styles (unmaintainable). A single CSS file with a component vocabulary was the missing piece.

The Debate Map

When HTML wins

HTML is the right format when: the document exceeds 20 lines, has multiple sections a reader needs to navigate, will be shared with people who don't edit it, will be read more than once, contains structured comparison data (tables, matrices), or needs to communicate hierarchy and emphasis to a non-technical audience.

When Markdown stays

Markdown is the right format when: the file is a README, AGENTS.md, CLAUDE.md, CHANGELOG, LICENSE, or any file an ecosystem routes to by exact filename. Also when the content will be loaded as model context repeatedly — Markdown's token efficiency is an advantage that HTML cannot overcome for this use case.

The false binary

The thread framing — HTML vs. Markdown — is misleading. They are not alternatives. Markdown routes and provides low-cost context. HTML operates and presents. The "new" in "HTML is the new Markdown" is about role, not replacement. The two formats belong in different layers of the same system.

What Changed After This Thread

  • The term "artifact" replaced "document" in common developer vocabulary for structured AI output.
  • Simon Willison's HTML explainer workflow became a widely-shared pattern within two weeks of the thread.
  • CSS-only styling systems for HTML artifacts saw immediate GitHub interest and several new projects appeared within the month.
  • "Scan-first" document design became an explicit requirement in AI-native team documentation guidelines.
  • The argument for Markdown as the routing/context layer and HTML as the render layer was widely accepted as the synthesis position.

Markdown routes. HTML operates. CSS renders. The three-layer model that emerged from this thread's synthesis is now the baseline assumption for AI-native documentation systems.
