Readworthy CLI Architecture

A two-phase CLI-first system for auditing Markdown spec ecosystems, showing token/context benefits, and converting selected docs into semantic HTML without breaking compatibility.

← Home Why CLI-first Two-phase workflow Commands
Decision: readworthy should be CLI-first with an optional agent skill layer. The CLI performs deterministic repo analysis, token auditing, validation, and conversion. The skill can orchestrate the CLI conversationally.

Why CLI-first

NeedBest fitReason
Repo scanningCLIRequires filesystem access, deterministic paths, and repeatable output.
Token estimatesCLIRequires consistent file-size and tokenizer heuristics.
Markdown-to-HTML conversionCLITransformations should be reproducible and testable.
Migration reasoningAgent skillUseful for explaining tradeoffs and generating user-facing recommendations.

Two-phase workflow

Phase 1: readworthy init

The first run is a learn/prime step. It audits the repository, identifies Markdown spec files, estimates context cost, classifies compatibility, and outputs a proposed migration plan. It should not modify files.

Phase 2: readworthy convert

The conversion step writes selected HTML files, preserves required Markdown compatibility files, optionally creates lightweight loaders, validates output, and reports actual savings.

Accuracy considerations

Spec detection

Recognize common Markdown spec names and classify them by compatibility requirement, not by filename alone.

README.md, AGENTS.md, SKILL.md, install.md, design.md, brand.md,
product.md, validation.md, components.md, prompts.md, workflows.md,
architecture.md, CHANGELOG.md, CONTRIBUTING.md, LICENSE

Token estimates

Use a consistent tokenizer when available. Fall back to transparent heuristics such as characters divided by four. Always label estimates as estimates unless a tokenizer is used.

Safe defaults

Never overwrite Markdown by default. If generating loaders, back up originals and show a diff.

Semantic output

Generate semantic HTML with article, header, main, section, aside, table, pre, and code. Avoid div soup and inline styles.

CLI + skill relationship

CLI   = analysis engine, converter, validator, reporter
Skill = conversational interface, recommendation explainer, workflow guide

The optional skill should teach the agent how to run readworthy init, interpret its plan, ask for approval when appropriate, and then run readworthy convert. It should not duplicate the transformation logic.

Product positioning

Not: Markdown-to-HTML converter.
Better: AI documentation architecture optimizer for structure, compatibility, and context efficiency.
