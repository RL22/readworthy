Using HTML as an AI-Native Operational Format

A comprehensive summary of Thariq Shihipar’s “HTML is the new markdown” thread and the broader ecosystem response.

← Home Summary Core Argument Final Takeaway
Primary source: Thariq Shihipar on X — original thread

Executive Summary

Anthropic engineer Thariq Shihipar sparked widespread discussion across the AI developer ecosystem after publicly stating that HTML is becoming the new default format for AI-generated outputs.

“HTML is the new markdown.”
Source: Thariq Shihipar on X

The thread proposed a shift away from large AI-generated Markdown documents toward HTML-based operational artifacts generated by tools like Claude Code. The discussion centered on a broader observation: AI systems now generate enormous amounts of documentation, humans increasingly do not edit those files manually, Markdown’s traditional strengths are becoming less relevant for long generated outputs, and richer structured HTML outputs are often easier to consume and operate.

In Thariq's Words

From Using Claude Code: The Unreasonable Effectiveness of HTML — the longer-form follow-up to the thread.

On the limitations of Markdown

"I find it difficult to read a markdown file of more than a hundred lines. I want richer visualizations, color and diagrams and I want to be able to share them easily."

"I'm also increasingly not editing these files myself, but using them as specs, reference files, brainstorming outputs, etc. When I do make edits, I'm usually prompting Claude to edit them, which removes one of markdown's largest benefits."

On the power of HTML

"There is almost no set of information that Claude can read that you cannot fairly efficiently represent with HTML."

"HTML can allow you to interact with the document, for example you might want to ask it to add sliders or knobs to adjust a design or allow you to tweak different options in the algorithm to see what happens."

On team collaboration

"The chance of someone actually reading your spec, report or PR writeup is much much higher if it's in HTML."

"I find this often works better than the default Github diff view, and I attach a HTML code explainer to every PR I make now."

On practical productivity

"I'll ask Claude to build me a throwaway editor for the exact thing I'm working on. Not a product, or a reusable tool, but a single HTML file, purpose-built for this one piece of data."

"The trick is always to end with an export: a 'copy as JSON' or 'copy as prompt' button that turns whatever I did in the UI back into something I can paste into Claude Code."

On the human element

"Making HTML documents with Claude is just more fun and makes me feel more involved and invested in the creation, and that by itself is enough."

"I had begun to fear that because I had stopped reading plans in depth I would simply have to leave Claude to make its choices. But I am happy to say instead that I feel more in the loop than ever before when using HTML."

The Core Argument

The central thesis was that Markdown has become the default AI output format because it is simple and portable, but AI-generated documentation is now so large that the readability and editing advantages of Markdown are diminishing.

“Markdown over 100 lines nobody reads anymore.”
Source: Threads summary/reaction

The key insight was not that Markdown is bad. The key insight was that AI-generated operational documents are increasingly difficult to read, navigate, and operate on as plain text.

Why HTML Was Proposed

1

Better readability

HTML enables hierarchy, visual grouping, cards, callouts, tabs, collapsible sections, embedded visuals, interactive controls, richer spacing, and better typography.

2

Operational interfaces

HTML can turn AI output into dashboards, research surfaces, monitoring tools, and action-oriented interfaces instead of passive documents.

3

AI now edits the files

Markdown historically won because humans could edit it easily. In AI workflows, users increasingly ask the model to regenerate or revise sections instead.

Simon Willison’s Experiment

Simon Willison tested the idea by asking Claude to generate HTML explanations for technical systems, obfuscated code, and security-related examples. His experiment reinforced the idea that HTML explanations can be easier to understand than giant Markdown blobs.

Reference: Simon Willison — “The unreasonable effectiveness of HTML”

The Emergence of Artifacts

A major conceptual shift emerging from the thread was the increasing use of the term artifacts instead of notes, docs, or Markdown files. This aligns with Claude Artifacts, generated dashboards, operational interfaces, dynamic HTML systems, and interactive AI outputs.

The ecosystem increasingly described AI outputs as living operational systems, interactive interfaces, and personalized tooling surfaces rather than passive documentation.

Progressive Disclosure and Context Architecture

A parallel conversation around Claude Skills became highly relevant. A widely shared analysis summarized the deeper architectural lesson with the idea that a skill is a folder, not only a Markdown file.

“A skill is a folder, not a file.”
Source: Medium — “Claude Code Skills Are Not Markdown Files”

This analysis explained how agent workflows can structure references, templates, scripts, assets, hooks, and operational context using progressive disclosure rather than giant monolithic Markdown files.

Tokenomics and Context Concerns

A significant criticism raised during the discussion was that HTML can increase token usage. Critics argued that markup introduces additional tokens, generated interfaces may increase context cost, and humans may lose lightweight co-authoring workflows.

Important constraint: HTML is not automatically more efficient. HTML becomes useful when semantic structure reduces cognitive load, improves scanning, enables progressive disclosure, and prevents repeated prose.

Supporters countered that structure can reduce effective context waste when paired with selective loading, collapsible sections, operational views, and targeted references.

The Emerging Stack

One clear ecosystem summary described a stack where agents, MCP, Markdown, and HTML work together. In this model, Markdown stores lightweight structured knowledge, HTML artifacts provide operational interfaces, agents interact with both layers, and users operate through generated surfaces.

“Agents + MCP + Markdown + HTML”

Final Takeaway

The thread was ultimately not about replacing Markdown with HTML.

It was about a broader realization: AI-generated outputs are evolving from documents into operational artifacts.

As AI systems generate larger outputs, richer workflows, operational dashboards, dynamic interfaces, and structured research systems, the ecosystem is increasingly exploring HTML artifacts, progressive disclosure, operational surfaces, structured interfaces, and context-aware documentation systems while still preserving Markdown for portability, compatibility, lightweight routing, and repository conventions.
