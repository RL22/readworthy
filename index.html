AI-native docs worth reading.

★ Star on GitHub

How we got here

AI tools now generate enormous amounts of documentation: specs, summaries, agent instructions, research briefs, workflow guides. All of it lands as Markdown. The format works well for a 20-line README. It breaks down at 200 lines. Long AI-generated Markdown is hard to read, harder to navigate, and impossible to scan.

In 2025, Anthropic engineer Thariq Shihipar named what many teams were already feeling:

"The chance of someone actually reading your spec, report or PR writeup is much much higher if it's in HTML."

Thariq Shihipar, Anthropic

The ecosystem agreed. HTML artifacts are becoming the default output surface for serious AI workflows. The tooling to produce them consistently, readably, and without a framework did not exist. Readworthy is that tooling.

The solution

Readworthy is a single CSS file and a component vocabulary. Link it from any HTML file and your AI-generated output becomes structured, readable, and agent-friendly: headers, callouts, spec cards, code blocks, warnings, checklists, and more.

Core model: Markdown routes. HTML operates. CSS renders.

Use Readworthy when the document is no longer just writing. When it becomes a spec, an operational artifact, an agent instruction set, or a reference surface that needs to be read by both humans and machines, that is when HTML earns its place. When you need a README or a quick note, keep Markdown.

The HTML tax

HTML costs more tokens than Markdown when loaded as model context. The same content as HTML can run 1.5 to 2 times more tokens. This is real and worth understanding.

Readworthy documents are render targets, not model context. Your AI generates the HTML once; your team reads it many times. The token overhead lives in the generation step, not in every subsequent read.

Keep Markdown as your routing and compatibility layer. Use HTML for the outputs that need to be read.
